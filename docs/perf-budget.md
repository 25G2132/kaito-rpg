# 重さの目安（段階1の結果）

2026-11-18 測定。試作：`?spike`（`src/spike/perfSpike.ts`）。

## 測ったもの

- キャラ：VRoid 見本キャラ AvatarSample_A（VRM1.0、軽くする設定なし）を4体
  - ファイル 17.8MB、三角形 約3万／体、絵 27枚／体（2048² が4枚、1024² が3枚 ほか）
  - 絵が使う画面のメモリ（GPU）の見積もり：約140MB／体 → 4体で約560MB
- 敵の仮の形 3体、影あり（1024²）、髪や服の揺れもの あり

## 決めたこと

- **戦いで同時に映す人数**：味方4人＋敵（3〜5体）。減らさない。
- **影・揺れもの**：使う。
- **画面の細かさ**：上限 2（3 にしても見た目はほぼ同じで、ほかの機械で重くなるだけ）。
- **キャラ1体の目安**（iPhone の人と、読み込みの時間のために控えめにする）：
  - 三角形：4万まで（VRoid の標準のまま書き出してよい）
  - 絵：VRoid の書き出しで「マテリアルの削減」を使い、絵を少数の大きな1枚にまとめる。絵の大きさは 2048 まで。目標は **GPU 40MB／体・ファイル 8MB／体** 以下。
  - 理由：Galaxy S26 では問題ないが、iPhone の Safari は1つのページが使えるメモリが厳しい。見本キャラのままだと4人で約560MB になり、落ちるおそれがある。iPhone は手元にないので、数字で控えめに抑える。
  - 敵や場所の絵も、合わせて 200MB 以内を目安にする。
- **モデルの読み込み**：本番のキャラは公開してよいもの（自分たちで作ったもの）だけを置く。見本キャラは再配布できないので、試作でしか使わない。
